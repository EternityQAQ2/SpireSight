## 本轮完成：输入语义与模型对照

- 采用敌人ID绑定、当前费用有效期/FREE_ATTACK后重读、hp_loss直接失去生命与retaliation_damage格挡前荆棘伤害的区分；game纯函数与decision输入模块承担各自职责。旧self_damage保留给旧policy，避免模型把两种损失混用。未知值保持null。
- X次攻击次数未知时不伪造一次反伤；目标荆棘数值或状态列表未知时不提供精确turn_search，避免摘要说未知而试算按0。补充回归测试；8题输入哈希不受这些边界修复影响。
- 用户只授权现有DeepSeek。Flash/Pro普通模式、相同1024上限、真实AdvisorService与冻结三路知识证据；Git c1dd6b6加载旧输入，8题各重复2次、三组共计划48次。
- 实际付费47次决策、80请求、485999 token（小于500000上限），43正常返回、4次Pro空白；最后一项预算保护取消，未请求。没有继续调题或补跑。
- 共同15对：旧Flash/新Flash/新Pro，合理交付前缀11/12/8、待判断4/3/2、明确差解0/0/1、空白0/0/4；理由错误8/7/0、原提案非法或致死后缀2/1/0。字段不能混成准确率。
- 费用计划有局部改善（两份免费攻击超费后缀→0），群战选择仅一次改善、另一次退回；精英最后1费没有改善，单体药水误当全体减伤仍存在。新Flash共同样本token多6.2%，延迟基本相当。没有总体智力或平均楼层提升的证据。
- 保留小修正，不切Pro、不全局开启思考、不恢复战术接管。详见EXPERIMENTS当前章节与evals的decision_quality输入/复核。

## 已上线的事实

- 本机配置：deepseek-flash、thinking=disabled、adaptive=false、OPENAI_MAX_TOKENS=1024。CLI参数可覆盖；不要写出密钥或base_url中的认证信息。
- remote.py在显式启用thinking时会把输出上限至少提到16384，low也不是硬token预算。不要以为给旧比较脚本传4096就只会花4096；查看实际request_options和全局预算。
- 原8题实验用1600输出上限、冻结top_k=6证据；线上 `AdvisorService` 战斗实际是 `min(top_k,4)`。这些实验是受控对照，不能直接当作完整线上表现。
- 线上已有唯一合法候选直接处理、短计划复用、重复状态去重。不要重复实现这些降本路径。
- 计划逐步检查费用、卡牌、目标；未知效果和不确定转移后观察，关键HP/盾/状态不符停止复用。完整提案不等于实际执行动作。
- 计划校验失败最多请模型再决策一次；战斗失败不规则接管。监听会暂停同一失败局面，避免反复付费。
- `policy.py` 等旧修复函数仍供历史评估/测试使用，不代表在线流程会采用它们。
- 已移除按“秒杀”字样拿单张攻击去校准整套计划、改写理由的逻辑；不要重加这个误判过的办法。

## 状态和工具

- API的hand、draw_pile、discard_pile、exhaust_pile是战斗区域。牌库SQLite是卡牌事实，不是当前玩家永久牌组。
- DeckTracker保留有来源、完整度、过时标记的观测；临时生成牌不直接算永久持牌。未知不是0。
- 动态牌面优先。力量、虚弱、缩小等已经体现在显示伤害/费用时不再叠加。
- 模型工具 `calculate_attack(decision_id,candidate_id)` 只算当前快照的一张指定攻击。历史expected_hp_after可选兼容，新schema不要求它，也没有工具置信度。
- 支持已验证目标修正、滑溜逐次实际失去HP、格挡先吸收；未知机制和必要数值缺失仍返回未知。
- 已核实药瓶皮套、永冻冰晶、历石不影响当前Attack直接伤害，不再阻断该计算。不是全局忽略这些遗物的其他效果。
- 每次工具调用都从同一快照开始，不能把几个返回的剩余HP拼成出牌序列预测；不能用单张结果否定多张组合击杀。

## 三路知识

- `data/sts2_facts.sqlite3`：只读事实和交互；`data/chroma`：语义攻略；`data/seeds.jsonl`：独立注入基线原则，非入库重建产物。
- auto组合seed → SQLite＋Chroma（不可用时JSON回退）；seed不占top_k。
- 修复了“岿然不动”误匹配“不动”状态的子串问题。
- 事实排序优先真实当前状态、敌人和候选；拾起时效果后排，未使用药水的同名状态不冒充已生效状态。
- 查询按战斗/选牌等场景组织，包含关键实体、手牌或有来源的牌组观测，不再序列化整个situation作查询。
- 这些改动提高相关内容覆盖、本地检索速度，尚无可靠的决策质量提升证据。

## 已实施：线上对齐与首轮攻击结果实验（默认未切换）

1. CLI和回放共用 `create_remote_backend`。新回放调用 `AdvisorService.run_once(force=True)`，走唯一候选、战斗检索条数、模型、校验/一次重决策及只读交付；没有动作执行器、没有规则接管。恢复录制时的context及牌组观测，不冒充连续游戏或StateBuilder重建测试。
2. `decision/context.py`复用原calculator给每个指定目标的合法攻击候选附最小 `attack_result`：status、hp_after、killed；未知保留reason且不伪造0。全局scope明确“每项从同一快照独立计算”。不排序或选择战术。
3. `OPENAI_PRECOMPUTE_ATTACKS=true`仅作为可选实验模式：战斗首轮给数值、不注册function tools。默认 **false**，原function calling继续使用；非战斗行为不受此开关影响。未改本机.env、thinking或输出上限。
4. 6个新局面、5次录制、6场战斗，两配置各重复2次，24个决策全部完成；33次请求、177421 token，低于20万预算。没有继续调提示、额外补跑或挑好答案。固定输入/复核见evals/fixtures的attack_delivery文件。
5. **未通过推广标准。** 工具组115317 token、首轮数值组62104（少46.1%）；均12/12返回。人工复核含理由、warnings和原始计划，明确错误回答3→8；其中数值/事实错误1→7，非法后缀各2（分类有重叠）。后缀被截断，不能称为已执行错误。平均回放决策3.142→2.123秒。成本目标达标、质量门槛失败，因此不切默认。

质量结论：首轮数值组两次都将单张打击后的11剩血当成两张结果；两次将10盾对8攻说成掉2血；两次把另一只敌人的荆棘归到当前目标。首步多数一致，未观察到战术提升。不能归因成“少一轮就必然变笨”，也不能把返回成功率当正确率。
