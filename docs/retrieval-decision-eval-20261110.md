# 2026-11-10 检索改进后的模型基准复测

本次没有观察到稳定的决策提升。8题第一动作全部相同；群战的局部算术修正了，但仍没有合理比较击杀攻击者能减少的生命损失。另有一题新增错误的易伤伤害比较。因此只能保留“检索内容覆盖与本地速度改善”的结论，不能宣称模型准确率或平均楼层提高。

## 对照方式

沿用上次固定的8个局面：debuff-order、partial-block、four-enemies、reward-exhaust、zero-cost-kill、cheap-lethal、boss-opening、reward-defense。原评分说明不发送给模型，不因本次答案修改评分标准。

- 基线：Git `932eb58`，已含名称误匹配修复，尚未应用本次事实排序与场景查询。
- 改进版：Git `72d9c7d` 的检索输出。
- 两边都使用既有20局面文件中的同一个完整状态，证据取自上一轮真实SQLite/Chroma/seed对照冻结文件。事实和攻略原文保留，不用本次模型答案补充知识。
- DeepSeek `deepseek-flash`，thinking=disabled，输出上限1600；均为生产当前提示词和同一计算器，不使用精简提示词或示例seed。
- 每题每边一次，顺序交替；SDK重试关闭，每次决策最多2请求，全局最多32请求、160000 token。
- 对实际发送内容核对：8/8组系统提示逐字相同，用户JSON除evidence外完全相同。只改变检索证据。
- 没有游戏操作，没有程序替模型改选战术。

“以前基准”是同一批题目；本轮重新调用两边，避免用历史旧答案和今天新答案直接对比。旧历史测评中的首领/30盾选牌还含已修复的名称误匹配，故这两题的旧输入不等同本轮Git基线。

这里审查的是原始建议与计划。执行程序仍会在不确定效果后停止复用并重新观察，不能把原始错误后缀直接说成实际发送给游戏的动作。

## 与历史结果的关系

核对上次结果后发现，6题旧版的首轮实际输入与这次旧版完全相同，部分答案仍变化。例如18血斩杀的旧版本次更合理。这说明单次调用存在波动，若只把旧答案与改进版新答案比较，会把波动误当作改进收益。本轮用同时间段的成对重测，没有把这类变化归因于检索。

## 后续判断

检索改进解决了信息排序和无关内容问题，本轮没有解决集中击杀、换血权衡及数值一致性。继续扩大知识量缺少本轮证据支持。下一步更值得逐项检查计算器返回未知的原因，或在同一基准上比较可接受延迟的推理配置/模型。没有据这次结果继续修改线上策略或增加评审模型。
