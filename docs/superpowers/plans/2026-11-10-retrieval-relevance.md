# 检索相关性改进计划

**Goal:** 优先提供当前决策所需事实，并用简短、按场景组织的查询检索攻略。

**Architecture:** 保持现有 SQLite、向量/JSON 攻略及 seed 组合。将无 I/O 的相关性规则放在 integrations/knowledge/relevance.py；common.build_query 保持原接口并委托查询构造，SQLite 负责读库，按规则排序后截取。seed、模型提示词、计算器、战术执行不改。

**Spec:** 用户批准事实排序和向量查询两项改进，要求善用 Git 并先本地提交。回退点为 932eb58，包含此前已存在的全部代码与实验资料，不推送远程。

## 约束和设计

- 战斗事实优先级：当前状态与敌人机制、对应交互/药水、持续遗物、其他说明，拾起时效果靠后；排序可解释，不维护逐张牌战术白名单。
- 非战斗优先候选实体及事件事实，再补当前状态、遗物和关联知识。
- 交互不能在排序前按旧 ID 截断。保留命中页面，按当前实体关联程度排序。
- 保持既有攻略配额和 top_k 约束，seed 仍独立注入；不增加在线模型或依赖。
- 查询按场景组织：战斗敌人/状态/手牌，选牌候选/已观测牌组；其他界面选项与必要描述。重复卡去重，保留升级，明确快照不完整/过时，不把战斗牌堆作为永久牌组。
- 不修改数据库内容或重建嵌入。先离线对照20个冻结局面，区分相关性、延迟与未经验证的模型收益。
