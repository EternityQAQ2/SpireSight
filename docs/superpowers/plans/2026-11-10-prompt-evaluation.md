# 日志决策对照实验 Implementation Plan

**Goal:** 用固定日志局面检验精简指令与数字对比示例能否改善决策，同时保留 SQLite、向量检索和 seed。

**Architecture:** 实验代码放在 evals，复用现有状态、检索、远程模型和计算器；生产默认提示词保持当前版本。每个局面的两种提示共享同一份冻结检索结果，只替换实验版 seed 表达。模型负责选择，程序只评分和检查合法性。

**Tech Stack:** Python、pytest、现有 OpenAI-compatible DeepSeek adapter、SQLite、Chroma。

**Spec:** 用户已批准上一条回复中的小实验：固定约 20 个日志局面，对比当前输入与精简规则加少量对比示例，记录质量、耗时和 token，控制 API 用量。

## Global Constraints

- 保留知识数据库、向量数据库和 seed；不重建或删除数据库。
- 不发送游戏动作，不改线上思考模式，不用程序替换模型战术。
- 保留用户已有未提交修改；直接在现有功能分支完成实验。
- 20 个完整状态快照分开发集和留出集；评分标准不发送给模型。
- 先选 8 个局面做成对 API 测试，每次最多 2 请求，总请求与 token 上限由脚本强制执行。
- 原始模型响应与检查结果分别保存；未知和有争议的战术不算确定错误。

## Review Focus

- 实验不能删掉 SQLite 和向量检索的原文或来源 ID。
- 抽牌后计划截断不能掩盖原始计划越过观察边界。
- 缺失响应和预算耗尽必须出现在结果中，不能只统计成功回答。
- 留出题评分规则不能泄漏到模型输入。
- 总请求预算涵盖工具后续请求和 SDK 重试（禁用 SDK 自动重试）。
