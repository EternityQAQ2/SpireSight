# 数值工具修复与模型对照计划

**Goal:** 提高单张攻击计算器可用性，并用固定基准比较token、决策质量、成功率和延迟。

**Architecture:** 游戏算术留在calculator，参数协议留在decision/tools。历史expected_hp_after可选兼容；对远程模型仅暴露局面ID与动作ID。数值检查不代替模型选择。比较摘要和候选模型仅在evals做实验，保留现有数据库、seed、检索与游戏执行接口。

**Spec:** 用户批准前一条回复的三个方向，要求完成修改后给出以token和质量等维度为中心的报告。基线为b264d85。

## 约束

- 仅解除已通过数据库和日志核实的无关阻断，不忽略所有未知机制。
- 计算范围为当前快照中一张指定攻击的直接伤害，仍不模拟回合、随机抽牌或战术。
- 先失败测试，再修复：三件遗物、已反映到牌面的玩家状态、真正未知、滑溜多段结算、可选预估参数。
- 更新项目skill及桥接脚本；历史传参仍可读取，新模型协议不要求先估算剩血。
- 固定上一轮8局面和修改后检索证据、普通模式、1600输出上限；比较旧工具Flash、新工具Flash、新工具Flash+两方案摘要、新工具Pro。每次决策最多2请求，总预算64请求/360000 token。
- 候选Pro使用同一授权服务，先验证/models可用；不提供新密钥、不切换提供商。
- 每个对照只改对应因素；原始输入/输出/工具结果留存，沿用原评分标准，未知和有争议选牌不算确定错误。
- 若出现明确候选收益且预算允许，再做少量重复确认；小样本不宣称平均楼层改善。

## 结果

- 32次决策尝试、49次模型请求，296027 token；Pro一次空最终内容。无思考模式、无游戏操作。
- 旧14次工具调用的未知6→0；四组共同字段明确错误各2题，无稳定质量提升。摘要组额外问题使含明确错误回答达到4/8，不推广；Pro较慢且空回复，不切换默认模型。
- 已应用工具修复，更新项目和已安装技能。没有修改数据库、seed、检索或战术执行。
- 全量234项：232通过、2项跳过；无预估HP的桥接脚本实际返回16伤、49→33，历史预估参数兼容测试通过。
