# 战斗试算评估

当前向模型公开的工具是 `calculate_attack`：从当前状态读取单张攻击牌、目标生命、格挡和已支持的目标修正，逐段计算并核对模型给出的预期生命。缓慢使用出牌前的当前 amount；力量等已体现在手牌伤害中，不能重复加入。未识别状态或遗物、随机攻击等返回未知。模型没有主动调用工具时，如果最终理由明确声称击杀，也会自动核对首个动作；确定不一致则最多要求模型重选一次。历史的 `evaluate_combat_plan` 保留供内部使用。

缓慢与易伤组合的取整依据 2026-11-05 局面单步观测：9 伤、易伤和缓慢 20%，造成 16 伤；出牌后缓慢显示 30%。多段攻击及其他增伤效果叠加的时序尚需更多实际观测，当前不推广到未知效果。

`evaluate_combat_plan` 只预测当前已观测回合。返回 `exact=false` 时，`unsupported_mechanics` 列出阻断完整预测的状态或遗物；费用检查仍可独立使用。拾取时生效的卷轴箱不会阻断战斗模拟，墨宝的滑溜按下一次失去生命仅 1 点处理。

运行 `python tools/eval_function_calling.py recordings/<session>.jsonl`，离线比较每次实际出牌后的敌人生命、能量和格挡。比较要求下一条记录仍在同层同回合，且卡牌效果受支持。击杀后游戏会重排敌人 ID，因此敌人生命以存活值集合比较；该指标不能识别两个同生命敌人之间的目标互换。抽牌、随机效果及未支持机制不纳入误差分母。

2026-11-04 22:44 的固定记录：修复前 77 次工具调用均未产生数值预测。修复后离线重算，79 个战斗决策中 66 个局面可建模；40 个可对照的出牌动作里，敌人生命、能量、格挡误差各为 0。剩余阻断机制主要是弱化、凶恶、残酷。真实 DeepSeek function calling 冒烟测试调用 1 次工具，墨宝局面返回 `exact=true`、伤害 1，模型最终回答不能击杀。

`data/run_stats.json` 和 `docs/run-stats.md` 记录每局工具有效次数、调用次数、错误次数，以及工具回包后的模型调用与 prompt tokens。后者是额外请求的原始输入量，含上下文重复部分，不等于净计费增量。平均楼层与胜率需用多局对照评估；单局结果不能证明提升。
